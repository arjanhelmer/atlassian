Designing Atlassian's New Navigation

Company Atlassian
Role Lead Designer
Launch October 2024 (EAP)
Scope 6 Atlassian products

One Navigation for All Products

Atlassian released Jira in 2002, with Confluence following in 2004. Since then, the product suite has grown significantly through both development and acquisition. As customers adopted multiple Atlassian products, the inconsistent navigation across products forced them to relearn the same tasks in different contexts. Finding work became a consistent pain point in user feedback.

On the engineering side, each product team had customised their navigation to quickly ship features and meet specific needs. While this helped teams move faster initially, the differences multiplied. Soon, simple updates required changes across multiple codebases, making even the smallest changes costly and complex. These fragmented codebases prevented us from creating the consistent experience our customers needed.

The solution: one navigation, one codebase. In October 2024, we unveiled the new navigation through an Early Access Programme to 6 key Atlassian products, significantly improving the experience that millions use every day.

Learning from the Past

This wasn't our first attempt. In 2018, Atlassian redesigned the navigation using a one-size-fits-all approach — applying an identical navigation to every product. The results weren't what we hoped for. We couldn't address each product's unique needs. The key lesson: consistency doesn't mean everything has to be identical. There has to be a balance between consistency and flexibility.

The Principles Behind the Pixels

Before starting any design, we needed guiding principles to make sound decisions. We believe customers should be able to move seamlessly between products, getting more value from using them together. This belief drove three core principles:

  • Maintain predictability and familiarity by repeating design patterns across all products wherever possible
  • Allow user control and customisation to show and hide what's relevant and what's not
  • Progressively disclose information to be approachable for new users while retaining the functionality needed by power users

From Top to Side

The most significant design decision was moving product navigation from the top bar to the sidebar. This unlocked key benefits:

  • Modern and familiar UI: Users today work across Google Workspace, Slack, and Microsoft Teams — all of which use a sidebar. By aligning with this industry pattern, we reduced cognitive load as users switch between tools.
  • Move quickly between projects: The sidebar provides the vertical space and information density needed for a bird's-eye view of work that wasn't possible with dropdown menus in the top bar. A product manager can check ideas for an initiative, review dependencies in a release, and see incoming support feedback — all from the sidebar.
  • Clear and streamlined top bar: With product navigation in the sidebar, the top bar is now consistently dedicated to universal actions like search and create, immediately discoverable no matter what product you're in.

Use, Iterate, Repeat

We co-created with customers from day zero. The design evolved through five phases of testing:

  • User research with 16 Jira users to learn how they navigate our products. Two clear needs emerged: users wanted to customise their navigation and needed better ways to find frequent items — which could potentially be solved by Starred and Recent.
  • Vision Lab prototyping — since static design tools can't capture navigation's full complexity, we prototyped with Atlassian's internal prototyping tool to validate complex interactions like drag-and-drop and accordion panels.
  • Chrome plugin with 160 users from a wide range of organisations and user types. Users loved the customisation options so much they wanted more — personalised project navigation and easier ways to hide sidebar items.
  • Low-code prototype to test refined designs. We discovered that while settings were initially harder to find, the location made sense once discovered, matching patterns in other tools. We decided to focus on onboarding users to settings locations.
  • Internal testing with Atlassians — key feedback around the discoverability of the sidebar collapse pattern. We quickly tested options and shipped the one that performed best.

Three Components to Rule Them All

When we audited the product suite, we discovered just how fragmented navigation had become. Each product team had built custom components, resulting in hundreds of components and 23 major inconsistencies between products. Through focused design sprints, we mapped overlapping components and discovered something surprising — most navigation needs can be met with just three reusable components:

  • Menu Button — the core clickable navigation element
  • Flyout Menu — for expanding contextual options
  • Expandable Menu — for hierarchical navigation with progressive disclosure

The power lies in their flexibility. Each component starts with required properties, but optional properties make them customisable. Need more context? Add a description. Want quick actions on hover? Add the actions property. Need to show it's expandable? Add a chevron indicator. This modular approach handles hundreds of navigation patterns with just three base components.

Sweating the Details

Navigation isn't just about moving between places — it's about understanding how everything fits together. The old navigation relied heavily on labels to show relationships and hierarchy, creating visual clutter.

Using design system spacing tokens, we built indentation directly into the components. But during internal testing, we discovered an unintended consequence: navigation items were getting truncated on smaller screens. The indentation showed hierarchy, but at the cost of readability.

Because we had built indentation into design tokens, we could adjust the entire system at once. With a single update to the spacing tokens, we found the sweet spot: a more compact indentation that maintained clear hierarchy while improving readability across all screen sizes.

Built for the Future

The new navigation is built on a modern tech stack with design system primitives, including built-in support for accessibility and RTL languages. Changes can be made once and applied everywhere.

To drive adoption, we created a navigation library as the single source of truth — including a Figma spec template guiding designers through accessibility, responsiveness, empty states, and content design, plus a component library with sticker sheets, implementation videos, and clear usage guidelines.
